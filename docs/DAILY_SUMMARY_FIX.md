# 일별 요약 및 종가 표시 — 2026-09-22

SOXL 체결 요약이 과거 전체 매칭 원장의 길이를 세던 문제를 수정했다. 선택한 미국 거래일의 SOXL 주문 ID와 연결되고 수량이 양수인 체결만 사용하며, 분할 체결은 주문별 한 건으로 센다. 같은 필터를 체결 상세에도 적용한다. 서로 다른 HYXL 계좌의 주문 ID는 별개로 취급한다.

RP에는 주문가능금액의 평가 보정 설명 대신 실제 이자 수익을 표시한다. lst의 `myStockSummary.ts`는 `ls-rp-income:` 입금 원장과 정산 관측의 RP 누적액을 대조한다. 같은 날짜의 RP 원금을 합산해 그 날짜의 이자/매수 원금 수익률을 계산하고, 날짜별 수익률을 기하 연결한다. 표시값은 실현·세전 누적 운용수익률이며 연이율이 아니다. 원금 메타데이터가 없거나 누적액 대조가 맞지 않으면 수익률을 추정하지 않는다. 원화로 납부된 세금은 USD 이자에서 임의 차감하지 않는다.

lst의 일별 발행 상세는 `buildSettlementSummary`로 생성한다. 상세 본문의 RP 평가보정 설명이 다시 요약으로 들어오는 것을 막고 Tail 요약을 보존한다. 보관된 정산 입력만 재발행했으며 정산·주문 작업은 재실행하지 않았다. RP 과거 요약 12건도 이자 원장과 대조해 수정했다.

운영 대조에서 같은 관측 시각의 revision을 문자열로 정렬해 9가 10·11보다 우선되던 조회 문제도 발견했다. DB 원본 bigint 컬럼으로 정렬해 정정본을 선택하도록 고치고 PostgreSQL 회귀 테스트를 추가했다.

주식/현금 비중 아래에 선택 날짜의 종가, 전일 대비 금액과 등락률을 추가했다. SOXL과 KODEX 하이닉스만 표시한다. ACE는 사용자 요청으로 종가 표시에서 제외하며 기존 자산 및 실제 주문 기록에는 영향을 주지 않는다. 상승은 초록, 하락은 빨강이다.

- SOXL: lst `daily_prices.close_price`와 `prev_close`. `change_pct`의 단위 혼동을 피하기 위해 종가로 등락률을 직접 계산한다.
- HYXL: kst `myStockQuotes.ts`가 Naver Finance의 날짜별 종가를 읽고 직전 거래일 종가를 연결한다. 장 종료 이전의 당일 가격을 확정 종가로 저장하지 않는다. 확정된 날짜는 소스 서버 디스크에 캐시한다.
- 가격은 기존 보고서 JSON의 `quotes`에 보관한다. 새 DB/테이블/매매 조회 권한은 추가하지 않았다. 가격이 없거나 조회에 실패해도 정산 발행을 막지 않는다.
- 과거 SOXL 123건·HYXL 58건과 기존 정산 배치에 확인 가능한 가격을 보충했다. 가격이 없는 날짜에 현재가나 다른 날짜 종가를 대입하지 않는다.

검증: API 회귀 테스트 39개, Swift 모델 테스트 32개, 종가 화면 UI 테스트, 양쪽 source 타입 검사와 보고서 단위 테스트, lst 운영 회귀 테스트. 운영 데이터의 자산·현금·손익은 변경하지 않았다. Vercel과 보고서 소스 어댑터를 배포했으며 개인 iPhone 빌드도 설치했다.

소스 서버 변경 전 파일은 각 프로젝트의 `.my-stock-backups/20260922-summary-fix` 및 `20260922-quotes`에 보관했다. 실제 응답·가격 보충 계획·원본 데이터 백업은 로컬 `.local/`에 있으며 Git에 포함하지 않는다.

후속 kst/lst 작업에서는 기존 dirty worktree의 보고서 통합 변경을 보존한다. lst는 `myStockSummary.ts` 및 테스트, `myStockAdapter.ts`의 현재일 체결 필터·RP 요약·종가, `dailyReport.ts`의 정산 요약 연결을 함께 검토한다. kst는 `myStockQuotes.ts` 및 테스트, 어댑터의 종가 필드를 함께 검토한다. 두 소스의 `myStockReporting.ts`에는 선택적 `quotes` 필드가 추가되었다.
