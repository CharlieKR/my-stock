# 과거 기록 복원 및 조회 개선 — 2026-09-20

## 월별 수익이 비어 있던 이유

- HYXL의 6월 29일~7월 2일 Slack 원문에는 누적 손익이 없었다. 이전 계산은 모든 투자에 누적 손익이 있어야 합산할 수 있어 6월 종합 수익이 비고 7월 계산도 3일부터 시작했다.
- 연속된 거래일의 일별 손익이 있으면 `현재 자산 − 이전 자산 − 일별 손익`으로 순입출금을 추정한다. 누적 손익이 양쪽에 있으면 기존 원금 변화 계산을 우선한다. 중간 평일이 빠진 일별 손익은 여러 날의 수익으로 사용하지 않는다.
- 다른 투자가 처음 합산되는 날에는 그 자산 전체를 편입 원금으로 처리한다. 이전부터 보유한 자산이나 입금액이 신규 수익으로 잡히지 않는다. 원화 합산은 날짜별 환율을 사용한다.
- 실제 입출금 원장으로 확정한 결과가 아니므로 복원 성과에는 계속 **추정** 표시가 붙는다. 누적 손익 원문을 임의로 채우거나 변경하지 않았다.

## Slack에는 있었지만 수집에서 빠진 기록

SOXL 4월 21·22·23·24·27·28·29·30일, 5월 1·4일의 정산 10건을 복원했다. 이 메시지에는 `일일 리포트` 제목이 없고 `종합 (원금 …)` 구역에 계좌 자산이 있었다. 제목에 의존하던 스레드 필터를 수정했으며, 개별 전략 자산을 종합 자산으로 읽지 않도록 회귀 테스트를 추가했다.

원문을 다시 조회해 자산·현금·주식평가·누적 손익·수익률을 대조한 뒤, 기존 `reporting.legacy_reports`의 해당 10개 행만 갱신했다. 원래 대기 기록을 정산 기록으로 바꾼 것이므로 총 일별 기록 수는 187개로 동일하다. 매매 테이블은 변경하지 않았다. 전체 월별 성과는 3월부터 9월까지 표시된다.

다음 날짜는 확인한 Slack 스레드에 정산 자산 자체가 없어 복원하지 않았다.

| SOXL 날짜 | 확인한 내용 |
| --- | --- |
| 3월 24일 | 주문 검증만 있고 정산 자산 없음 |

| 4월 16일 | 날짜 제목만 있고 정산 응답 없음 |

월별 수익은 누적 손익 등 양 끝의 계산 근거가 있으면 계산할 수 있다. 따라서 일별 관측이 비어 있다는 사실과 해당 월 수익 계산 가능 여부는 구분한다.

## 기간 표시

막연한 `일부 기간` 대신 첫 기록일은 `3.25부터` / `6.29부터`, 진행 중인 달은 `9.18까지`, 필터로 잘린 달은 `선택 기간`, 계산 자체가 불가능하면 `근거 부족`으로 표시한다. 월 상세에서 실제 시작·종료일과 계산 이유를 확인할 수 있다.

## 차트와 날짜 이동

- 총자산 카드 안으로 선택 상태를 분리해 커서 이동 시 월별 표 전체가 다시 계산되지 않도록 했다.
- 날짜와 Y축 범위를 시리즈 변경 시 준비한다. 날짜 탐색은 이진 탐색을 사용하며 같은 날짜 안에서 움직일 때는 선택 상태를 다시 쓰지 않는다.
- SOXL/HYXL Daily에서 오른쪽 스와이프는 이전 기록, 왼쪽은 다음 기록이다. 기록 없는 날은 건너뛰고 끝에서는 그대로 유지한다. 수직·대각선 스크롤은 날짜를 바꾸지 않는다.

검증: Node 36개, Swift 모델 32개, 양쪽 탭 좌우 전환·세로 스크롤 및 차트 선택/해제 위치 유지 UI 테스트 2개 통과. 시뮬레이터와 실기기 빌드 성공. 운영 API에서 복원 10건 및 세 범위의 월별 수익을 확인했고 최근 정산값은 기존 Slack 대조 결과와 동일했다. API를 배포하고 개인 iPhone에 업데이트를 설치했다. 기기가 잠겨 있어 이번 업데이트의 실기기 실행 점검은 하지 못했다.
